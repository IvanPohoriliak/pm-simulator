# Assistant stage 4 — Specify

Part of the Requirements Assistant: the assistant's main rules (the main file in the assistant folder) and `team.md` apply.

## For this team
- Checkpoint: yes — show the short summary and stop for the BA's approval.
- Template: default. Language: English.

**Goal:** a specification the team can build from.

## Before you start
- Intake approved (status line), or the Intake checkpoint is off in `team.md`. If not, say so and stop.
- Unresolved blocking decisions: you may draft, but mark each one visibly. Don't present the spec as final while any remain.

## Structure
Use the team's template from `team.md`. If none:
Objective · Current behaviour · Proposed behaviour · Scope · Out of scope · Business rules · Functional requirements · Non-functional requirements (only relevant ones) · Dependencies · Assumptions · Open questions / blockers · References

Leave out sections that add nothing. Use the team's terms.

Before saving: check every `file:line` you cite (main rules, rule 4).
Save as `spec.md` in the item's drafts folder with `Status: Draft`.

## End
If Specify is a checkpoint: show the spec, ask the BA to approve it or say what to change, and stop.
